DEMO 03

DOM-based XSS – URL-Fragment

Bei DOM-based XSS verarbeitet JavaScript im Browser nicht vertrauenswürdige Daten und fügt sie unsicher in die Webseite ein.

Aufgabe

Lade beide Beispiele und vergleiche, wie der Browser den Inhalt verarbeitet.

Aktueller Modus: Noch kein Beispiel geladen
Hier erscheint die Vorschau.

Test-Payload in der URL: 

<div style="...">
    <h2 style="...">⚠️ SICHERHEITSWARNUNG</h2>
    <p style="...">Deine Sitzung ist abgelaufen!</p>
    <p>Bitte bestätige deine Identität, um fortzufahren.</p>
    <button
        onclick="alert('Simulierte DOM-XSS-Attacke!')"
        style="..."
    >
        Sitzung wiederherstellen
    </button>
</div>

Wie funktioniert die sichere Variante?

Bei innerHTML interpretiert der Browser übergebene Inhalte als HTML-Code. So kann es dazu kommen, dass eingeschleuste HTML-Tags und Event-Handler ausgeführt werden. Wird stattdessen textContent verwendet, behandelt der Browser die Inhalte als reinen Text. So wird verhindert, dass es zur Ausführung kommt.
